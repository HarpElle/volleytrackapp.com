# volleytrackapp.com review, 2026-09-04

Reviewed by Claude Code (Fable 5.1). Read-only pass over a fresh clone of `main` at `c25e410`, GitHub PRs, branches, Dependabot, Pages config, and the live site.

## Executive summary

- **What it is.** A 13-page static marketing and support site for the VolleyTrack app (GitHub Pages from `main`, apex domain, Cloudflare in front, HTTPS enforced). No build step, no dependencies, no CI, no analytics. Hand-written HTML plus one 189-line stylesheet and one small progressive-enhancement script.
- **Where it stands.** Live and healthy in the `prelaunch` state (last content change 2026-07-18). All 13 URLs return 200, the custom 404 works, `www` and `http` redirect to the apex, internal links and image references all resolve, and the privacy and terms pages are substantive owner-authored policies dated 2026-07-17. Zero open PRs, one branch, zero Dependabot alerts.
- **The one thing to do next.** Make the two forms honest: today both the launch-updates form and the account-deletion form hand off to `mailto:` and then show a "Request received" style confirmation even when no mail client opened, so a Google Play deletion request can silently vanish. Wire a tiny endpoint (or at minimum reword the confirmation) before the store submission that the VolleyTrack app repo is now planning after PR #51 merged today.
- Everything else is launch-flip preparation: store badges and URLs, og:images, the P0 help articles, and self-hosted fonts, in that order.

## Issues

### P0

None. Nothing is broken for a visitor today.

### P1

1. **Deletion form confirms success it cannot verify.** `assets/site.js` (form handler) sets `location.href` to a `mailto:` and then hides the form and shows `#del-confirm` ("Request received.") in `delete-account.html`. On a desktop with no mail client, nothing is sent and the user is told it was. This is the URL declared to Google Play for account deletion. Fix: post to a real endpoint (reuse the HarpElle feedback-relay Worker pattern that emails via Resend) and keep `mailto:` only as the no-JS fallback; until then change the panel copy to "Your email app should have opened with the request ready to send. If it did not, email info@volleytrackapp.com."
2. **Launch-updates form has the same failure mode.** `download/index.html` form calls `form.reset()` after the `mailto:` hand-off with no visible confirmation at all, and no list is actually being collected. Fix: same endpoint as above with a short thank-you panel, or replace the form with a plain "Email us" link until one exists.
3. **Third-party font call on every page contradicts the site's own privacy stance.** All 13 pages load Google Fonts (`fonts.googleapis.com` and `fonts.gstatic.com`, visitor IP sent to Google), `assets/site.js` says "no third-party calls", and `privacy/index.html` says nothing about the website itself. Fix: self-host and subset Archivo 700/800 and Roboto Mono 300 to 700 under `assets/fonts/` with `font-display: swap`, remove the two `preconnect` tags, and add a two-sentence "This website" paragraph to the privacy policy. README already lists this as a to-do.

### P2

4. **Dead `tokens/` directory.** `tokens/*.css` (five files) is referenced by nothing; `assets/site.css` already inlines the tokens. `tokens/fonts.css` also `@import`s a different Roboto Mono axis set than the pages use. Fix: delete the directory or document it as the canonical source and generate `site.css` from it.
5. **Repo carries about 9 MB of unused images.** 141 of 186 files in `assets/images/screenshots/` and all 12 top-level files in `assets/images/` (including `app-store-badge.svg` and `google-play-badge.png`, which are needed at launch) are not referenced by any page. Not a page-weight problem, but it doubles clone time and hides which assets are real. Fix: prune to referenced files plus the two badges, or move the full set to the screenshots source repo.
6. **Em-dashes in visible copy (22 across 10 pages)** conflict with the HarpElle brand rule. Fix: replace with commas, periods, or colons during the next copy pass; `spectator-view/index.html:52` is a representative example.
7. **Seven "Soon" placeholders in `help/index.html`** are non-links styled like cards. Honest, but the help search only ever finds one real article. Fix: publish the P0 help set (Quick Start, Just Score vs detailed, Start and share Spectator View, Correct a score) before launch; drop the rest from the list until written.
8. **No `og:image` / `twitter:image` on any page.** README says intentionally omitted until the 1200x630 art exists. Fix: produce one site-wide image and one for `/spectator-view/`; `assets/images/volleytally-og.png` (unused) shows the VolleyTally precedent.
9. **768 inline `style=""` attributes** across the pages (105 on the home page alone). Every copy or spacing change is a search-and-replace. Fix: fold the repeated card, eyebrow, and paragraph patterns into `site.css` classes during the launch-flip edit; not worth a separate pass.
10. **`status/CURRENT.md` says "One dirty local file"** but names neither the file nor the checkout, and no checkout of this repo was found under `/Users/jasonpaschall/HarpElle` (depth 3). Unverified. Fix: whoever has that checkout commits or discards it and records which it was.

## Suggestions (value over effort)

1. **Launch flip as one PR.** Prepare a `launch` branch now with store badges, `MobileApplication` JSON-LD on `/download/`, the "Get launch updates" CTAs swapped to "Download", and the prelaunch strip removed, so the day the app is approved is a merge, not a rewrite. (High value, M)
2. **Add a `Link:` / `Cache-Control` sanity note and a link checker.** No CI exists and none is needed for deploys, but a single `workflow_dispatch`-only job running `htmlproofer` or `lychee` (Linux, a few seconds) would catch broken links before Pages publishes. Keep it manual so it costs nothing. (Medium value, S)
3. **Share the relay Worker with VolleyTally.** `volleytallyapp.com` has the same forms problem; one Worker with an allowlist of two origins serves both. (Medium value, S once the first exists)
4. **Confirm the VolleyTally cross-join copy** against the real iOS and Android builds before launch, per the README gate. If it is not verified by submission day, remove the "or VolleyTally" lines rather than ship a promise. (Medium value, S)
5. **Retire `docs/CLAUDE_DESIGN_HANDOFF_REQUIRED.md`** or rewrite it; it describes the VolleyTally site and points at an SMB path. (Low value, S)
